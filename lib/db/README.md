# Database bootstrap seed

For deployments that run migrations externally (rather than in managed application startup), run `pnpm --filter @workspace/db run deploy:prepare`. This runs `migrate` then `seed` against `DATABASE_URL`. Do not add this command to managed startup that already owns migrations. To run only the seed, use `pnpm --filter @workspace/db run seed`.

For first provisioning set `SUPERADMIN_EMAIL` (valid email), `SUPERADMIN_NAME` (nonempty name) and a strong `SUPERADMIN_PASSWORD` through protected deployment secrets. Never put credentials in command arguments or logs. The seed trims the name/email and lowercases the email. If email/name are both omitted it skips; malformed/partial configuration fails. Remove the initial password secret after provisioning; no default credential is provided.

Replit production startup and `pnpm start:selfhost` always invoke this seed before serving the API. On a fresh database, all three `SUPERADMIN_*` settings are required to create the initial administrator. Later starts preserve existing credentials; seed failure stops startup. The preview-only recovery secret is not a seed input. Apply schema changes before startup using Publish for managed databases or the approved external migration process for self-hosting; the self-hosted startup command does not run migrations.

The seed creates one active native `superAdmin` with an Argon2id password hash, no provider account and no invitation/session/email. Sign in through local staff password login; SMTP is not required for that login. It preserves existing administrators, including hashes and inactive status. A matching active administrator without a native hash may be initialized once with the explicitly supplied password. A different email or existing nonadmin must not be promoted or overwritten. Use authorized account administration for recovery; see `docs/auth/native-auth-migration.md`. Historical provider IDs remain preserved for schema compatibility, not sign-in.

Run disposable embedded PostgreSQL tests without connecting to production: `pnpm --filter @workspace/db run test:seed`.
