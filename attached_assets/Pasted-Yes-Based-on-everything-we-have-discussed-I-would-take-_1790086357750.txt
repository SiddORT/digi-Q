### My recommendation on the approach

I would **definitely go with one `Users` menu → three tabs** rather than three separate sidebar items.

The important improvement isn't really the tabs themselves. It's this model:

**Admin owns clinics → users inherit their valid clinic scope.**

So the person creating a Doctor doesn't have to think about the Admin relationship at all:

> **Select Doctor → Select valid clinics → Create & Invite**

And for a Receptionist:

> **Select Receptionist → Select valid clinics → Select branches → Create & Invite**

The system automatically derives the Admin relationship.

That makes the system much more "dumb-proof" while still keeping the backend strict.

The most important rule I would **not compromise on** is:

```text
Clinic → Exactly ONE Admin Owner

Doctor → ONE Managing Admin → Only that Admin's Clinics

Receptionist → ONE Managing Admin → Only that Admin's Clinics/Branches

This also makes your Doctor-created-clinic scenario very clean:

Admin A
   ↓ owns
Clinic A
   ↓
Doctor X

Doctor X creates Clinic B

Automatically:

Clinic B → Admin A
Clinic B → Doctor X

No extra Admin selection, no ambiguity, and no possibility of accidentally attaching the new clinic to the wrong Admin.
