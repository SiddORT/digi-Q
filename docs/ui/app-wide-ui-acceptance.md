# Current app-wide UI corrections and acceptance boundary

## Status and evidence rules

This is a **local, fictional-data UI correction record**, not hosted UAT repair or an unconditional “done throughout” assertion. The route ledger distinguishes a rendered initial state from successful interaction acceptance. Each conditional source consumer is accounted for separately and remains unverified per instance unless an executed named check establishes more. Unopened dialogs, unavailable devices and unexplored permission combinations are not silently accepted.

- [Current route and numbered-requirement table](app-wide-route-evidence.md).
- [Machine-readable route/role/state/source ledger](app-wide-ui-ledger.json): requested paths, resulting paths, viewports, geometry, failures, executed interactions, all 137 numbered findings, the 41-point requirement titles, and individually enumerated conditional consumers.
- [Fresh source inventory](surface-inventory.json): state criteria, role routes, forms, dialog placements, fields, actions and linked destinations. **Source enumeration is not rendered acceptance.**
- Reproduction: `scripts/app-wide-ui-ledger.mjs` consumes a broad Playwright JSON run followed by narrower correction-retest JSON runs. Later evidence replaces only the same named check, never unrelated failures. `scripts/app-wide-ui-contact-sheets.mjs` creates an offline index, not a new browser acceptance pass.

### Evidence freshness

- Before relying on checked-in results, run `node scripts/app-wide-ui-ledger.mjs --check`. A nonzero exit means stale evidence, **not** an application failure. `--refresh` updates the JSON and route table's stale labels without running a browser or refreshing acceptance.
- Older reports without run-time fingerprints are stale by design. Never attach today's hashes to an old run to make it appear current. Historical pass/failure and permitted-redirect observations remain in `historicalStatus` / `historicalDisposition`; conditional owners remain `unverified-per-instance`.
- Future workspace-regression runs record SHA-256 input maps in Playwright JSON `config.metadata.uiEvidence` before workers start and after they finish. Retain the JSON report under `generated-artifacts/`; screenshots/traces remain in ignored test output directories, never new Git evidence. Route attachments reference the run's starting digest and identify the browser project.
- To build a ledger from authorized local fictional-fixture runs: regenerate the source inventory with `node scripts/compact-ui-inventory.mjs`, then pass the JSON reports in chronological order to `node scripts/app-wide-ui-ledger.mjs <broad.json> [narrower.json ...]`. The inventory command refreshes source enumeration only. Each result remains bound to its own run; a newer narrow retest cannot make older unrelated results current.
- The dependency set is deliberately conservative: production UI/shared client source, public assets, all workspace fixtures/tests/geometry criteria, styles (including imports), routing owners, lockfile, package/TypeScript/Vite/Playwright configuration and ledger/inventory criteria. Byte-content hashes and relative filenames are reproducible across checkout locations; additions/deletions count as changes. A shared dependency change invalidates the whole affected run rather than guessing which conditional owners were rendered. Generated output and environment/secret values are excluded.
- A run whose inputs changed before completion is stale. Matching hashes establish **input freshness only**: they do not establish acceptance of nested states, authorization, UAT, real browser zoom or Safari/Firefox Add Staff behavior. Existing browser/access restrictions still apply. This guard never runs bookings, delivery, production writes or automatic browser refreshes.
- Guard regression checks: `node --test scripts/ui-evidence-freshness.test.mjs`.

### Offline contact-sheet freshness

- `node scripts/app-wide-ui-contact-sheets.mjs [local-capture-directory]` reads existing local `app-wide-ui-*` route captures only. The default is the workspace regression output directory. It does not navigate to the application, rerun fixtures, access databases, or refresh booking, delivery or production data.
- All generated sheets, the self-contained `index.html` and the provenance manifest `index.json` stay in ignored `generated-artifacts/app-wide-ui/contact-sheets/`. Regeneration removes obsolete numbered sheets so a smaller run cannot leave old pages mixed in.
- Every sheet and capture displays its originating run input SHA-256, report SHA-256 when available, and CURRENT / STALE / UNKNOWN input freshness. Exact route attachments must match ledger run provenance; a newer narrow retest cannot relabel an older capture. Both run endpoints are checked against the same conservative source/config fingerprint used by the ledger. Legacy, missing or invalid provenance remains UNKNOWN; changed inputs are STALE. Empty/incomplete capture sets are explicitly warned about, not accepted.
- These are **frozen snapshots**, not self-updating status screens. Their banners state when they were checked and warn that later changes require another offline generation or `node scripts/app-wide-ui-contact-sheets.mjs --check`. The read-only check exits nonzero for STALE/UNKNOWN evidence, changed/replaced captures or missing inputs; it does not rewrite the index or request new screenshots.
- Even CURRENT means input freshness at generation only. Contact-sheet inspection is not acceptance of initial geometry, interactions, nested states, authorization, hosted UAT, delivery or cross-browser behavior.
- Offline regressions (including synthetic-image rendering without an application server): `node --test scripts/app-wide-ui-contact-sheets.test.mjs`.

### Distinct states retained

- Booking tests cover pending selection, current-session loading, request failure/retry, no listed sessions, full/blocked sessions, bounded next-date search, next-date scope freshness, role/source entry, guest flow and mandatory mobile through review/submission. Mutations in these booking tests are simulated and cannot reach the backend.
- The broad route fixture rejects unknown reads with an explicit 501 contract gap and every write with 405. Missing responses are reported, not converted to empty success. Fictional populated clinic, location, doctor, patient, visit, audit and staff rows exercise ordinary list content and long names.
- Patient editor checks explicitly type fictional unsaved text, test Escape → Keep editing → Escape → Discard, then verify return focus and the filter drawer. This preserves the confirmation contract; pressing Escape on a dirty form is not supposed to close it silently.
- Tab controls inside intentional horizontal scrollers are not judged by document width alone. Record lead cells have separate child-containment assertions. The generic geometry sweep excludes table scrollers; it does **not** certify every sticky cell or every long table action. Those remain conditional-owner limitations unless named.
- Profile tests use actual App identity/role mapping, including a restricted custom receptionist, and verify no writes. Initial role fixtures are not proof of server authorization.
