Verification evidence

  • Workspace TypeScript checks passed.
  • 51 disposable backend integration tests passed, including linked creation, previews, permissions, idempotence, capacity, exceptions, rollback and unlinking.
  • Two new real PostgreSQL contention tests passed with distinct connections and observed lock waits: booking-first preserves the ticket and rejects conflicting hours; settings-first rejects stale booking without consuming a token.
  • 23 ticket/export browser regressions passed, including logo/QR embedding, print/download, revisions, errors, long text and bulk exports.
  • 14 list/status-count tests and 10 initial focused frontend logic tests passed.
  • The targeted browser pass used real provider password proof and fresh Super Admin-assisted guided registration, not a seeded clinic. It created linked Monday/Tuesday sessions immediately, used the new QR anonymously, issued a fictional ticket and showed it in queue/appointments with correct tab counts.
  • Browser conflict preview blocked a booked Monday timing change. Mobile settings and ticket receipt rendered cleanly.
  • The browser exposed a repeat-review submission latch. That was fixed; seven focused regressions passed, including repeated review after a conflict. Frontend typecheck passed afterward.

Verification limits

The corrected repeated-review interaction was confirmed with focused tests, not a second browser pass. Safe unused-day synchronisation is covered by backend tests; the browser's unused-day draft was discarded before this fix. The browser onboarding path was Super Admin-assisted; a new anonymous self-signup/email-delivery path was not exercised. Every page/role combination was not individually browser-tested.

Temporary booking data and provider credentials were cleaned up. Protected inactive development fixture ownership records remain where removal would require weakening database guards. No guards were disabled.

Making it available live

No production records were modified and nothing was published automatically. Publish the update, then use each existing clinic's Settings → Locations & Hours to enable linked owner consultations with the intended capacity and duration. Review the impact and apply. Existing QR destinations remain unchanged.

For new solo-owner clinics, linked sessions are configured during onboarding when the linked option is selected. Existing clinics are not silently converted.
